# PDF 切分工具 — PRD

> 日期: 2026-07-10 | 状态: ready-for-agent | 关联 spec: `docs/superpowers/specs/2026-07-10-pdf-splitter-design.md`

## Problem Statement

用户经常需要将一个多页 PDF 拆分为多个独立文件——按页归档、按章节分发、或按固定页数分批处理。目前工具箱缺少 PDF 处理能力，用户必须借助外部工具或在线服务完成切分，存在隐私风险且流程割裂。

## Solution

在工具箱中新增 **PDF 切分工具**，提供三种切分模式。用户上传 PDF → 选择模式 → 配置参数 → 一键生成 ZIP 包下载，全程在本地服务端完成，文件不离开自有环境。

## User Stories

1. 作为用户，我想要将一个 PDF 按每一页拆分为独立的 PDF 文件，以便单独归档或分发每一页
2. 作为用户，我想要按自定义页码范围拆分 PDF（如提取第 1、3、5-8 页），以便灵活地提取需要的部分
3. 作为用户，我想要按固定页数（如每 3 页）批量拆分 PDF，以便将长文档分成等量的小段
4. 作为用户，我想要在拆分后一次性下载包含所有结果文件的 ZIP 包，而不是逐个下载
5. 作为用户，我想要看到上传 PDF 的总页数，以便确认文件正确并选择合适的切分参数
6. 作为用户，我想要在输入页码范围时得到实时校验反馈（格式错误、页码重复、区间重叠），以便在提交前修正问题
7. 作为用户，我想要拆分后的文件名包含序号或页码范围，以便一目了然地识别每个文件
8. 作为用户，我想要选择是否保留原始 PDF 的元数据（标题、作者等），以便在有需要时保持信息完整
9. 作为用户，我想要在上传非 PDF 文件或加密 PDF 时收到明确的错误提示，以便知道如何处理
10. 作为用户，我想要在拖拽文件到上传区域时也能触发上传，以便操作更便捷

## Implementation Decisions

### 模块划分

**新增后端模块**:

- `PdfController` — REST 控制器，接收 multipart 请求，参数校验，返回 ZIP 流
- `PdfService` / `PdfServiceImpl` — PDF 切分核心逻辑，使用 Apache PDFBox
- `PdfSplitRequest` — 请求参数 DTO（mode, pages, everyN, preserveMeta）
- 错误码扩展 `ErrorCodeEnum`（PDF_4001 ~ PDF_4007, PDF_5001）

**新增前端模块**:

- `pdf-splitter/index.vue` — 完整工具组件，含上传区 + 配置区 + 结果区

**修改现有模块**:

- `pom.xml` — 新增 `pdfbox` 3.0.3 依赖
- `frontend/src/tools/registry.ts` — 无需修改（自动扫描）

### API 契约

```
POST /api/pdf/split
Request (multipart/form-data):
  file:          Binary   (必填, ≤50MB, application/pdf)
  mode:          String   (必填, 枚举: "by-page" | "by-range" | "by-n")
  pages:         String   (mode=by-range 时必填)
  everyN:        Integer  (mode=by-n 时必填, ≥1)
  preserveMeta:  Boolean  (可选, 默认 false)

Response:
  200: application/zip
       Content-Disposition: attachment; filename="pdf-split-result.zip"
  400: application/json { code, message, data }
  500: application/json { code, message, data }
```

### 技术决策

1. **PDF 库**: Apache PDFBox 3.0.3 — Apache 2.0 许可，与 MIT 项目完全兼容
2. **切分方式**: 逐页 `PDPage` copy + `PDDocument.addPage()`，每个输出 PDF 独立创建 `PDDocument` 实例，保证无页面重复、无内容变更
3. **输出方式**: `ZipOutputStream` 直接写入 HTTP response 流，不落盘临时文件
4. **页码范围语法**: 逗号分隔，支持单页 `N` 和区间 `N-M`，如 `1,3,5-8,10`
5. **页码范围校验**: 展开为 Set 后检测重复与重叠，前后端双重校验
6. **文件命名**: 含序号标识 — `_p页码.pdf` / `_p起始-结束.pdf` / `_part序号.pdf`
7. **加密 PDF**: 检测 `PDDocument.isEncrypted()`，拒绝处理并提示用户
8. **元数据保留**: 可选，勾选后通过 `PDDocument.getDocumentInformation()` 读取并写入各拆分文件

### 页码范围校验规则

校验分三层，按顺序执行：

```
Layer 1 — 格式校验:
  - 字符白名单: [0-9, ,-]
  - 不允许空值 (连续逗号、首尾逗号)
  - 区间起始 ≤ 结束

Layer 2 — 语义校验:
  - 展开区间为页码集合
  - 检查集合内是否有重复页码

Layer 3 — 边界校验:
  - 所有页码 ≥ 1
  - 所有页码 ≤ PDF 总页数
```

### 页面设计决策

- **布局风格**: 沿用现有工具的左右分栏（继承 `ToolPage.vue` 提供的容器），左侧上传预览区固定约 40% 宽度，右侧配置区 60%
- **上传区样式**: 与现有工具 textarea 风格统一 — 圆角边框 `border-slate-200 rounded-lg`，拖拽区域用虚线边框 + 图标引导
- **模式选择**: Radio Group 竖直排列，选中态 indigo 高亮（与侧边栏 active tool 风格一致）
- **配色**: 所有颜色使用 CSS 自定义变量（`var(--text-primary)`, `var(--border-color)`, `var(--accent-color)` 等），自动适配 5 套主题
- **响应式**: 小屏（< 768px）时左右分栏变为上下堆叠
- **状态管理**: 组件内 `ref` 管理本地状态（上传文件、模式、参数、结果），不引入全局 store

## Testing Decisions

### Seams（测试接缝）

主测试接缝在 **API 层**：通过 Spring MockMvc 发送 multipart 请求验证完整请求-响应链路。

### 测试策略

**后端 API 测试（MockMvc）**:

- 上传合法 PDF + `by-page` → 200 + ZIP 流含 N 个文件
- 上传合法 PDF + `by-range` + 正确页码 → 200 + ZIP 文件数匹配
- 上传合法 PDF + `by-n` + N=3 → 200 + ZIP 文件数 = ceil(总页数/3)
- 上传非 PDF → 400 + PDF_4001
- 上传加密 PDF → 400 + PDF_4003
- 页码范围超出总页数 → 400 + PDF_4004
- 页码范围格式错误 → 400 + PDF_4005
- N 为 0 或负数 → 400 + PDF_4006
- 页码范围存在重叠 → 400 + PDF_4007

**后端 Service 单测**:

- 验证拆分后每个 PDF 可正常用 PDFBox 打开
- 验证拆分后总页数 = 原始总页数（无丢失无重复）
- 验证 preserveMeta=true 时元数据传递

**前端组件测试**:

- 渲染模式选择三个 Radio，默认选中第一个
- 输入重叠页码时显示校验错误提示
- 未上传文件时"执行拆分"按钮禁用

### 测试参考

- 后端测试参考: 项目当前无现有测试，遵循 Spring Boot Test 标准模式（`@WebMvcTest` + `@MockBean` 或 `@SpringBootTest` + `MockMvc`）
- 前端测试参考: Vue Test Utils + `mount`，模式类似 `useClipboard` 的纯逻辑测试

## Out of Scope

- 加密 PDF 密码解密（提示用户暂不支持）
- 多文件批量上传（单次一个 PDF）
- 拆分后在线预览缩略图
- PDF 合并、旋转、重排等其他操作（本功能仅限切分）
- 自定义输出文件名模板（使用固定的序号命名规则）

## Further Notes

- PDFBox 的 `split()` 方法会创建与原文档共享资源的轻量 PDF，但我们的逐页复制方案创建完全独立的 `PDDocument`，确保拆分后文件完全独立、无共享引用
- 大文件（接近 50MB）场景下，`ZipOutputStream` 流式写入避免将所有拆分结果加载到内存
- 前端输入校验和后端校验使用一致的规则，但后端校验是权威来源（不信任前端）
